Requirements

ServerVersionJavaJar
Paper26.225 or newerPaper edition
Paper1.21.1121 or newerPaper edition (1.21.11 build)
Spigot26.225 or newerSpigot 26.2 edition
Spigot1.21.1121 or newerSpigot 1.21.11 edition

Each jar only works on its own platform and version: PvpBot uses server internals to create the bots, so a Paper jar won't start on Spigot and vice versa. The features are the same in every edition (see Spigot edition).

Steps

  1. Stop the server.
  2. Put the right jar in the plugins/ folder.
  3. Start the server. PvpBot creates plugins/PvpBot/config.yml with every setting commented.
  4. As an op, run /pvpbot spawn. If a bot appears, you're set.
Updating from an older version You don't need to delete config.yml. New settings missing from the file use their default value; /pvpbot settings marks them with * until you change them with /pvpbot set.

Permissions

PermissionDefaultGrants
pvpbot.adminopEvery /pvpbot (alias /bot) and /ghost command.

Regular players need no permission to command the bots you hand them: they do it by typing in chat (see Companions).

Plugin files

Everything lives in plugins/PvpBot/:

FileContents
config.ymlSettings, presets, skins, name tables, the companions' world.
bots.ymlThe active bots, brought back after a restart if bots-relog is on.
factions.ymlFactions, members, relations, leaders, overfactions, per-faction settings and kit tables.
kits.ymlSaved kits.
scripts.ymlSaved scripts.
paths.ymlPatrol routes.
ownership.ymlWhich player owns which bot.
skin-cache.ymlSkins already fetched, so restarts don't ask Mojang again.
ghost-recordings/Paths recorded with /ghost record.

After editing a file by hand, run /pvpbot reload.

Compatible plugins

SkinsRestorer

Optional. If it's installed, PvpBot stores each fetched skin directly in its storage, so SkinsRestorer doesn't overwrite it with a default one when the bot joins.

Login plugins (AuthMe, LoginTo)

A bot can't type /login, so login plugins would keep it locked forever (the usual symptom is a bot that hops on the spot and takes no damage). With auth-autologin: true, on by default, PvpBot registers every bot as already logged in. Nothing changes for real players. See Troubleshooting if that isn't enough.

Protection (WorldGuard, GriefPrevention, claims)

Every block a bot places or breaks goes through the server's normal events, so protection plugins see it and can refuse it. The same goes for the rails and carts of cart PvP.
