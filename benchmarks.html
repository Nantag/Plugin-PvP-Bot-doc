Benchmarks

How many bots a Paper 26.2 server carries, what they cost in tick time and memory, whether it stays healthy over a long fight, and how the bots fight.

In short On the test machine a server holds 20 TPS with up to about 300 bots fighting. 100 fighting bots use 7 ms of the 50 ms each tick has, and about 3 MB of memory each. Ten minutes of non-stop fighting, with 332 bots spawned and 308 killed, gave no errors and no memory growth.

Test setup#

Date26 October 2026
ServerPaper 26.2 build 134, Java 25.0.3, -Xmx4G (6 GB for the 250+ runs)
PvpBotThe Paper 26.2 jar built from the current source (next update)
WorldFlat, no mobs, no structures, view and simulation distance 6, difficulty hard, nobody online
PluginsPvpBot only
MachineIntel Core i7-14700HX laptop (20 cores), 32 GB RAM, Windows 11

A server's main thread runs one core, so a slower CPU gets fewer bots. Treat the numbers as relative: twice the bots roughly costs twice the tick time. Every measurement is two 10-second windows of Paper's /mspt, taken after the bots had run for 30 seconds. Memory is the live heap after a full garbage collection.

Load: bots standing and bots fighting#

Idle: the bots stand where they spawned with their AI running and nobody to fight. Brawl: bot-vs-bot on, every bot fighting those around it. Everyone has Resistance V, so nobody dies and the count holds, but every swing, hit, knockback and decision still runs. A tick has 50 ms; past that the server drops below 20 TPS.

Stability: ten minutes of real fighting#

30 bots, bot-vs-bot on, nothing keeping them alive. A bot that dies is removed, so every 10 seconds the count is topped back up to 30. Spawns and removals churn the whole time, which is where leaks show.

Sizing a server#

  • Up to 50 bots: unnoticeable, about 3 ms a tick.
  • 100 bots: about 7 ms, comfortable alongside a normal player count.
  • 200 bots: about 20 ms, under half the tick, if the rest of the server is light.
  • Over 250: near the limit even on a fast desktop CPU, and lower on most hosts.
  • Spawn big groups in batches of a few at a time rather than all at once, and give the server about 3 MB a bot on top of what it already needs.

Running them yourself#

The scripts are in PvpBot's source, next to the plugin:

python pvpbot-paper/bench/bench.py                    # the load table: idle and brawl, 10 to 200 bots
python pvpbot-paper/bench/bench.py --only brawl --steps 250 300 350 400 --xmx 6G
python pvpbot-paper/bench/soak.py --bots 30 --minutes 10
python pvpbot-paper/fighttest/fighttest.py            # the fight tests

Each one starts its own throwaway server from an unpacked Paper install (PAPER_HOME), needs an accepted eula.txt (EULA_FILE) and writes its results to .cache/.
